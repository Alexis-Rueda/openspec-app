01 · Concepto

¿Qué es OpenSpec?

Es una herramienta de desarrollo dirigido por especificaciones. En lugar de pedirle a la IA que programe directamente, primero acuerdas qué se va a construir en un documento versionado. Ese documento es el contrato que humanos y agentes siguen.

📋

Specs como fuente de verdad

La carpeta openspec/specs/ describe el comportamiento actual del sistema. Todo cambio parte de ahí.

🔀

Cambios propuestos

Cada nueva funcionalidad vive en openspec/changes/ como una propuesta revisable antes de tocar el código.

🤖

Pensado para agentes

Genera instrucciones para Claude, Cursor y otros, con salida --json para integrarse en pipelines.

02 · Workflow

El flujo de trabajo

El camino por defecto tiene cuatro fases. Las de terminal (openspec) gestionan el estado; las del chat (/opsx:) ejecutan el trabajo con la IA.

  1. 1

    /opsx:propose

    Describes la intención y OpenSpec redacta una propuesta de cambio con requisitos y specs afectadas.

  2. 2

    /opsx:apply

    La IA implementa el código siguiendo la propuesta aprobada, fase por fase.

  3. 3

    /opsx:sync

    Se reconcilian las specs con lo realmente construido para que la fuente de verdad quede al día.

  4. 4

    /opsx:archive

    El cambio completado se archiva y las specs quedan como el nuevo estado base del proyecto.

03 · Balance

Ventajas y desventajas

Ninguna metodología es gratis. Esto es lo que ganas y lo que cuesta al adoptar OpenSpec.

+ Ventajas

  • Intención acordada antes de escribir código.
  • Menos alucinaciones: la IA trabaja contra una spec concreta.
  • Historial revisable de decisiones en control de versiones.
  • Onboarding más rápido: las specs documentan el sistema.
  • Salida --json para automatizar en CI/CD.
  • Independiente del asistente (Claude, Cursor, Copilot…).

− Desventajas

  • Curva de aprendizaje y disciplina inicial de proceso.
  • Overhead para cambios triviales o prototipos rápidos.
  • Las specs desactualizadas engañan si no ejecutas sync.
  • Requiere un asistente de IA compatible para brillar.
  • Herramienta joven: API y comandos aún evolucionan.
  • Otro artefacto más que mantener en el repositorio.
